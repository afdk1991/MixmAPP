## 0. 阅读前必读：这是「双态基线」快照，不是最终态

本轮为**多人并行改造**（version-lead / catalog-lead / android-lead / frontend-lead / deploy-lead 同时在改码）。本报告在盘点过程中观察到了两次真实变化，必须先说清楚，否则数字会被误读：

| 观察项 | 本会话早段读到的值 | 本会话后段读到的值 | 说明 |
| --- | --- | --- | --- |
| `version.json` | `{next:"0.0.0", build:100, channel:"preview", released:[]}` | `{next:"1.0.1", build:101, channel:"release", released:["1.0.0"]}` | version-lead 已把仓库版本态由预览升级为 `V1.0.0` 正式发布 |
| `git status --short` | `46 M` + `32 ??` | `65 M` + `32 ??` | 并行改造持续写入，工作区有大量在途改动 |
| `scripts/version.mjs` | 14,937 B / 373 行 | 16,024 B / 18:04 mtime（已重写） | 新版引入 `releasedVersion/buildVersion`，取「最新已发布正式号」而非 `next` |

因此本报告中所有「仓库当前态」均指**盘点时刻的快照**；所有「生产运行态」是**另一套独立事实**。二者当前并不一致，这本身就是三大根因之一（见 §6）。

> **核心结论（先给答案）**：仓库侧「预览版」已被 version-lead 基本清除并升级为 `V1.0.0`，但**生产 `cloud.mixm.top` 至今仍跑旧构建**（`/healthz` 与 `/meta` 实测 `version=0.0.0-preview`）。数据、图片、原生观感的修复都还卡在「仓库改完 → 未部署上线」这一步。
